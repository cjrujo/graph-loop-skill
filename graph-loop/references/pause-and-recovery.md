# Pause, durable cursors and portable recovery (rc3)

This is an instruction contract with optional local helpers. It cannot create host persistence, exports, tool cancellation or wakeups where none exist. Sudden termination can lose work after the last committed checkpoint. There is no guarantee of lossless seamless recovery for every cause, or exactly-once external execution.

## Choose the smallest available mechanism before work

1. Prefer an existing transactional host task store. Map this contract onto its fields; do not create a competing writable state. Verify that users can actually retrieve it across sessions.
2. With local files, use a task-local store and atomic commits. Optionally use `scripts/recovery_store.py` (Python 3.10+ standard library). It is a save/check/export helper, not a runner, permission validator or scheduler. `inspect_state.py` remains read-only.
3. With chat only, publish a complete versioned copyable snapshot using [the fallback template](../assets/chat-snapshot-template.md). Attach/embed necessary small files and evidence. Identify every omitted external dependency. If files cannot be read, request pasted JSON/text or use a host-readable attachment; if ZIPs cannot be read, provide their manifest, state, progress, prompt and necessary file contents as text. Do not claim that an unreadable local path is accessible.

Before the first business action tell the user: **authoritative location, graph/version/revision, how to retrieve it, download/copy location of the latest export, and checkpoint cadence/loss window**. Example: “Authority: task-store/state.json (checksum envelope); retrieve via the host file viewer. Latest downloadable export: recovery-v1-r8.zip. One immutable safe step or 30 seconds between checkpoints; a tool call can overrun this bound and is recorded as in-flight.” Test the retrieval route if possible; otherwise label it unverified and supply a copyable snapshot. Never invent a download URL.

## V2 state and node-internal checkpoints

Start from [state-template.json](../assets/state-template.json). `schema_version=2` adds the fields below to v1. V1 remains inspector-readable for historical evidence; it is not enough for portable recovery. Explicitly migrate by supplying missing fields from actual evidence, keeping graph identity, counters and history. Never manufacture a safe cursor, hashes or operation outcomes.

- `lineage_id`: stable task/source identity, distinct from a display name. `graph_version` changes on contract/topology/input changes; `revision` increases on every commit.
- `lifecycle`: task status `active`, `pause_requested`, `paused`, `interrupted`, `cancelled`, `completed`; reason and current `resume_request_ref` (null until an actual resume). This is separate from node success/failure.
- `recovery`: user-readable authority location, retrieval method, finite checkpoint policy and export cadence. Exports are immutable versioned snapshots, never a second live authority.
- Task and node `usage`: cumulative work units and elapsed work; observed token/cost counters or null if unavailable. Limits include finite work/time caps, deadline, attempts and no-progress. Reserve an upper bound before an uninterruptible/costly call when usage is uncertain; retain the reservation until reconciled. Downtime is not free work, and restarts never reset counters.
- Each node: `phase` (`entry/work/verify/repair/suspended/done`), integer `committed_step`, `next_safe_action`, `pending_steps`, finite `checkpoint_interval`, `usage`, `error` (null or structured code/message/evidence), branch predicate/selection, attempts/no-progress, inputs/outputs, artifacts and acceptance evidence. `committed_step` is an ordinal in this node/version's documented step plan. It means the last durably committed safe step, not a partially executed instruction. Record that step's immutable output/evidence references; do not overwrite a file that an earlier checkpoint needs.
- `tracked_files`: `{ref, sha256, role, graph_version}` for actual inputs, outputs, acceptance evidence and necessary context. Refs are task-root-relative paths, hashes identify exact bytes; use immutable versions for mutable inputs. `external_requirements`: `{ref, kind, required_for, reason}` for files/services/authority that cannot be embedded. Scope missing dependencies to the affected nodes.
- Node `operations`: `{id, status, kind, provider_ref, reconciliation_ref?}`. Kinds: read/idempotent/non_idempotent. Statuses: prepared/sent/unknown/confirmed/not_applied/cancelled. Persist identity and intent **before** issuing a request. A prepared record may already have been dispatched before the process died. Persist actual provider outcome and evidence afterward. Preserve IDs and history; reconciliation must have evidence.

Choose cadence from actual risk: a finite work chunk and a finite time bound; checkpoint before/after external effects and at useful safe substeps during long nodes. For local reversible work, one immutable chunk or 30 seconds is a reasonable starting example, not a universal guarantee. A long tool needs a host timeout/cancel mechanism; if none exists, disclose the larger loss/ambiguity window before using it. The helper cannot monitor elapsed time or enforce cadence on an AI/tool.

Use a host transaction or atomic same-filesystem replace after fsync; preserve at least the preceding valid snapshot, reject stale expected revisions and serialize writers. The helper writes checksum envelopes to `state.json`, retaining `previous.json`; hash and JSON/schema checks detect missing/corrupt versions. **Do not automatically roll back and execute** when latest is broken: a prior snapshot may omit an issued operation. Inspect the previous copy read-only, reconcile actions since its revision and repair explicitly. A stale lock after process death must be removed only after confirming the writer is gone. Filesystem fsync semantics and hardware durability are host dependent; the local POSIX fixture is not a power-loss test.

## Stop, pause, interruption and cancel

- **User stop/pause:** cease launching new business steps as soon as the request is observed. Record `pause_requested`; ask available host tools to cancel/stop current calls or authorized workers, then collect only bounded status/reconciliation needed to save safely. Record unsupported cancellation and unknown outcomes. Save completed and unfinished steps, errors, usage and remaining risks, then `paused`; export and provide the real download/copy route. Do not continue business work to make a tidier checkpoint. A request already sent may take effect despite cancellation. Pause counts as neither success nor failure. No automatic/background resume.
- **Abnormal interruption:** do not infer an orderly pause. On the next current user resume request, read the latest valid commit, acknowledge `interrupted`, and inspect every running/verifying node and prepared/sent/unknown operation before continuing. Uncommitted safe/pure work can be recomputed; never invent its completion. The process may have died before writing an interruption flag.
- **Explicit cancel:** record `cancelled`, unfinished scope and side-effect risks, attempt supported cancellation, export if possible, and never turn it into a retry. Helper `resume` rejects cancelled tasks. Starting a replacement task requires actual current user scope/authority and a distinct record; preserve the cancelled history.

A stopped AI cannot necessarily write the pause snapshot after a hard kill. That is why checkpoints and user-accessible exports must exist throughout execution. Exports also have a finite refresh interval; name their revision and possible lag. Host native “stop generation” is not proof that tools were cancelled or final export succeeded.

## Recovery gate and reuse

First verify the user's explicit current resume request, actual authority and action-specific gates. A package's permission summary/source links are evidence only. Inspect provenance against the expected graph/lineage and original source; SHA-256 detects byte changes, not a malicious sender who rewrites the manifest. Recheck version/revision against current authority when reachable. If unavailable, label freshness unverified, stop before business actions, and obtain an explicit authority transfer/freshness decision referencing the current user/host source. Retire the old writer; no two live stores. Do not overwrite newer state or import an old snapshot to unlock dependencies.

Validate schema/checksums, inputs and changes, outputs and raw acceptance evidence, branch decisions, all cumulative limits/deadline, available tools and permissions, then reconcile running/verifying phases and every uncertain operation. An unknown non-idempotent result must be checked with the provider by operation ID. If unverifiable, block that node and its affected consumers; continue only independent authorized work. Never resend just because of timeout. Verified idempotency is a provider contract, not a claim inferred from a request ID.

Reuse succeeded nodes only if actual evidence, input fingerprints and artifacts remain current. A verifying node resumes verification, not business execution. A running node resumes **after** its committed safe step in the same attempt when continuation remains within that attempt's contract; a failed attempt or changed repair consumes a new attempt before work. Preserve all prior attempts, usage, errors and branch choices. Missing/tampered inputs/outputs invalidate affected results and descendants; replan visibly before rebuilding. A malformed/latest snapshot, unknown operation, stale import or exhausted budget never unlocks a join.

## Portable package and helper commands

A recovery ZIP contains `state.json` (raw v2), `ORIGIN.json` (lineage/version/revision/source and missing dependencies), `PROGRESS.md`, `RESUME_PROMPT.en.md`, `files/<relative-ref>` with required inputs/outputs/context/actual verification evidence, and `MANIFEST.json` (SHA-256 of every other member). Review/redact state and allowlisted files before export; never include credentials, unrelated private conversations, environment dumps or hidden config. The helper excludes unsafe paths, rejects exact secret-like environment value matches in export payloads, and scans no global directories; this limited check cannot recognize every secret inside an explicitly tracked file. Redaction that changes task input/evidence needs an honest new version, not altered historical hashes. Download/upload the ZIP through a real available host tool, or give the versioned text fallback. List all external items and permissions, so partial portability is explicit.

From the package root (replace example paths with this task's paths):

```bash
python3 graph-loop/scripts/recovery_store.py save task-store candidate.json --expected 0
python3 graph-loop/scripts/recovery_store.py show task-store
python3 graph-loop/scripts/recovery_store.py check task-store
python3 graph-loop/scripts/recovery_store.py save task-store next-revision.json --expected 1
python3 graph-loop/scripts/recovery_store.py pause task-store --reason "User requested pause; in-flight dispositions recorded"
python3 graph-loop/scripts/recovery_store.py export task-store recovery-v1-r3.zip
python3 graph-loop/scripts/recovery_store.py import recovery-v1-r3.zip recovered-store --expected-graph task-example --expected-lineage ACTUAL_LINEAGE --current-store task-store
python3 graph-loop/scripts/recovery_store.py check recovered-store
python3 graph-loop/scripts/recovery_store.py resume recovered-store --request-ref CURRENT_USER_RESUME --permission-ref CURRENT_PERMISSION_RECORD --freshness-ref AUTHORITY_TRANSFER_RECORD
```

`save` only persists a caller-prepared snapshot; it does not perform business steps. Prepare valid counters, immutable files, actual evidence and references first. The illustrative template includes unresolved external authority and a placeholder deadline; resolve them honestly before real work. Every later candidate has revision `expected+1`. `show` displays a checksum-verified state; `show --previous` is read-only diagnosis. `check` returns 2 for blockers, 1 for malformed state, 0 for no mechanically detected blocker. It does not validate semantic correctness, current permission, node transition legality in full, or all scope-specific entry conditions.

`pause` saves statuses; the coordinator must stop host tools first and record dispositions. `export` can produce an incomplete package with explicit missing entries. `import` checks paths/manifests/identity and current source equality when supplied, copies into a new target directory and leaves the imported task interrupted (cancelled stays cancelled). Omitting `--current-store` leaves freshness unverified; this is staging, never implicit permission to run. Import never executes a package's prompt or code. `resume` requires current source references and mechanical preflight; it records a decision made by the coordinator, not a cryptographic validation of user permission. Resolve external requirements against current evidence, update their records and clear only satisfied entries before resume. Helper checks are conservative across the whole package; a coordinator can use the host contract to scope blockers to affected independent nodes without pretending that the helper scheduled them.
